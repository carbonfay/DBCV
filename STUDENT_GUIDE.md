## Шаг 1: Ознакомиться

### Что такое DBCV? (Простыми словами)

**DBCV** - это платформа, где можно создавать ботов (например, для Telegram) **без написания сложного кода**.

Представьте конструктор LEGO, но для ботов:
- Вы берете готовые блоки (интеграции)
- Соединяете их между собой
- Получаете готового бота

**Пример:** Хотите бота, который отправляет сообщения в Telegram? Берете блок "Telegram Send Message", настраиваете его, и готово!

### Что такое интеграции? (Простыми словами)

**Интеграции** - это готовые "блоки" для работы с разными сервисами.

**Примеры:**
- Telegram интеграция - позволяет боту отправлять сообщения в Telegram
- OpenAI интеграция - позволяет боту использовать ChatGPT
- Google Sheets интеграция - позволяет боту читать/писать в таблицы Google

**Ваша задача:** Создать такие "блоки" (интеграции) для разных сервисов.

### Что такое пресеты? (Простыми словами)

**Пресеты** - это готовые "шаблоны" для типовых задач.

**Примеры:**
- IF/ELSE пресет - "если условие выполнено, сделай одно, иначе другое"
- Loop пресет - "повтори действие несколько раз"
- Delay пресет - "подожди 5 секунд перед следующим действием"

**Ваша задача:** Создать такие "шаблоны" (пресеты) для разных задач.

### Ваша задача (Что именно нужно делать?)

**Ваша задача:** Реализовать интеграции и/или пресеты.

**Как это делать:**
1. **Выбрать задачу** из списка (например, "Telegram Send Photo")
2. **Использовать AI** для написания кода (ChatGPT, Claude, Cursor и др.)
3. **Проверить код** - убедиться, что он работает
4. **Протестировать** - проверить, что интеграция работает в боте
5. **Записать видео** - показать, как это работает
6. **Создать Pull Request** - отправить код на проверку

**Важно:** Вы **НЕ пишете код вручную**! Вы используете AI-инструменты, которые будут писать код за вас. Ваша задача - правильно объяснить AI, что нужно сделать.

### Обзор процесса работы

Весь процесс состоит из 7 основных шагов:

1. ✅ **Ознакомиться** - понять что такое DBCV, интеграции и пресеты
2. ✅ **Выбрать задачу** - выбрать интеграцию или пресет из списка
3. ✅ **Установить программы** - установить AI-инструменты, Git, Docker и др.
4. ✅ **Установить проект** - настроить backend и frontend
5. ✅ **Реализовать и протестировать** - создать интеграцию с помощью AI и проверить её работу
6. ✅ **Записать видео** - показать результат работы
7. ✅ **Создать Pull Request** - отправить код на проверку

## Шаг 3: Установить необходимые программы

### Шаг 3.1: Установить AI-инструмент ⭐

**Это самый важный шаг!** Без AI-инструмента вы не сможете выполнить задание.

#### Что такое AI-инструменты?

AI-инструменты - это программы, которые помогают писать код. Они понимают ваши запросы на русском языке и генерируют код за вас.

#### Какие инструменты можно использовать?

Вы можете использовать **ЛЮБЫЕ** из следующих инструментов (или их аналоги):

##### 1. Cursor (Рекомендуется) ⭐

**Что это:** Редактор кода с встроенным AI-ассистентом.

**Как установить:**
1. Перейти на сайт: https://cursor.sh
2. Нажать "Download" (Скачать)
3. Установить программу (как обычную программу)
4. Открыть Cursor
5. Зарегистрироваться (можно через GitHub или Google)

**Как использовать:**
- Открыть файл в Cursor
- Нажать `Ctrl+K` (Windows/Linux) или `Cmd+K` (Mac)
- Написать запрос на русском языке (например: "Создай интеграцию для отправки сообщений в Telegram")
- AI сгенерирует код

**Плюсы:**
- ✅ Работает прямо в редакторе кода
- ✅ Понимает контекст вашего проекта
- ✅ Бесплатный план доступен

##### 2. GitHub Copilot

**Что это:** Расширение для VS Code и других редакторов от GitHub.

**Как установить:**
1. Установить VS Code: https://code.visualstudio.com
2. Открыть VS Code
3. Перейти в Extensions (Расширения) - иконка слева
4. Найти "GitHub Copilot"
5. Нажать "Install" (Установить)
6. Войти через GitHub аккаунт

**Как использовать:**
- Начать печатать код
- AI будет предлагать варианты автоматически
- Нажать `Tab` чтобы принять предложение

**Плюсы:**
- ✅ Работает прямо в редакторе кода
- ✅ Понимает контекст вашего проекта
- ✅ Бесплатный план доступен для студентов

##### 3. Codeium

**Что это:** Бесплатная альтернатива Copilot.

**Как установить:**
1. Перейти на сайт: https://codeium.com
2. Нажать "Get Started" (Начать)
3. Выбрать редактор (VS Code, PyCharm и др.)
4. Следовать инструкциям по установке

**Плюсы:**
- ✅ Полностью бесплатный
- ✅ Работает как Copilot
- ✅ Не требует подписки

##### 4. Codex (ChatGPT для VS Code)

**Что это:** Расширение для VS Code от OpenAI, которое интегрирует ChatGPT прямо в редактор.

**Как установить:**
1. Установить VS Code: https://code.visualstudio.com
2. Открыть VS Code
3. Перейти в Extensions (Расширения) - иконка слева
4. Найти "Codex" или "ChatGPT"
5. Нажать "Install" (Установить)
6. Войти через OpenAI аккаунт (или создать новый)

**Как использовать:**
- Открыть файл в VS Code
- Нажать `Ctrl+Shift+P` (Windows/Linux) или `Cmd+Shift+P` (Mac)
- Ввести "Codex" или "ChatGPT"
- Выбрать команду и написать запрос
- AI сгенерирует код прямо в редакторе

**Плюсы:**
- ✅ Работает прямо в VS Code
- ✅ Не нужно переключаться в браузер
- ✅ Понимает контекст файла
- ✅ Можно задавать вопросы и уточнять

##### 5. ChatGPT / Claude (через браузер)

**Что это:** AI-чатботы, которые могут писать код.

**Как использовать:**
1. Открыть сайт: https://chat.openai.com (ChatGPT) или https://claude.ai (Claude)
2. Зарегистрироваться (если еще не зарегистрированы)
3. Написать запрос (например: "Создай интеграцию для Telegram Send Message на Python")
4. Скопировать код из ответа
5. Вставить в файл

**Плюсы:**
- ✅ Работает в браузере
- ✅ Не нужно ничего устанавливать
- ✅ Можно задавать вопросы и уточнять

**Минусы:**
- ⚠️ Нужно копировать код вручную
- ⚠️ Не понимает контекст вашего проекта автоматически

## Шаг 4: Установить backend и frontend

### Шаг 4.1: Клонировать репозиторий

```bash
git clone <URL_РЕПОЗИТОРИЯ>

```

### Шаг 4.2: Настроить файл окружения

1. Скопировать файл окружения:
   ```bash
   cp env.example env.dev
   ```

### Шаг 4.3: Установить и запустить Backend

#### Вариант 1: Через Docker (рекомендуется)

**Запуск:**
```bash
docker-compose -f docker-compose.dev.yml --env-file env.dev up -d
```

**Примечание:** Файл `env.dev` автоматически используется через настройку `env_file` в `docker-compose.dev.yml`.

**Проверка статуса:**
```bash
docker-compose -f docker-compose.dev.yml ps
```

**Просмотр логов:**
```bash
docker-compose -f docker-compose.dev.yml logs -f backend
```

**Остановка:**
Сочетание клавиш CTRL+C в терминале или 

```bash
docker-compose -f docker-compose.dev.yml down
```

#### Вариант 2: Без Docker

**Установка зависимостей:**
```bash
cd backend
pip install -r requirements.txt
pip install -r requirements_integrations.txt
```

**Настройка базы данных:**
1. Убедитесь, что PostgreSQL запущен
2. Создайте базу данных (если еще не создана)
3. Запустите миграции:
   ```bash
   alembic upgrade head
   ```

**Загрузка начальных данных:**
```bash
python initial_data.py
```

**Запуск сервера:**

**Способ 1:** Использовать python main.py (рекомендуется):
```bash
cd backend
python main.py
```

**Способ 2:** Скопировать env.dev в .env и запустить через uvicorn:
```bash
# Из корня проекта
cp env.dev backend/.env
cd backend
uvicorn app.main:app --host 0.0.0.0 --port 8003 --reload
```

**Способ 3:** Использовать переменные окружения напрямую (Linux/Mac):
```bash
cd backend
export $(cat ../env.dev | grep -v '^#' | xargs)
uvicorn app.main:app --host 0.0.0.0 --port 8003 --reload
```

**Примечание:** Config.py настроен на загрузку переменных из файла `.env` в директории backend. Для использования `env.dev` скопируйте его в `backend/.env` или используйте `python main.py`, который автоматически загрузит переменные окружения.

**Проверка работоспособности:**
```bash
curl http://localhost:8003/health
```

Backend должен быть доступен на `http://localhost:8003`

## Шаг 5: Реализовать задачу и протестировать

### Шаг 5.1: Создать ветку в Git

**Что такое ветка?** Это копия проекта, где вы будете работать над своей задачей.

#### Обновить main ветку

```bash
# Переключиться на main
git checkout main

# Получить последние изменения
git pull origin main
```

#### Создать ветку для задачи

```bash
# Для интеграций: integration/{service}_{action}
# Примеры:
#   integration/telegram_get_updates
#   integration/openai_chat_completion
#   integration/stripe_create_payment

# Для пресетов: preset/{preset_name}
# Примеры:
#   preset/switch
#   preset/delay
#   preset/loop

git checkout -b integration/telegram_get_updates
# или
git checkout -b preset/switch
```

#### Создать структуру папок (если нужно)

```bash
# Если папка для сервиса еще не существует
mkdir -p backend/app/integrations/telegram
```

### Шаг 5.2: Использовать AI для написания кода

**Это самый важный шаг!** Здесь вы будете использовать AI-инструменты для создания кода.

### Частые проблемы и решения

#### Проблема: Конфликты при merge

**Решение:**
```bash
# Влить изменения из main
git checkout main
git pull origin main
git checkout integration/your_branch
git merge main

# Разрешить конфликты вручную
# Затем:
git add .
git commit -m "resolve merge conflicts"
```

#### Проблема: Забыл что-то добавить в коммит

**Решение:**
```bash
# Добавить файлы
git add forgotten_file.py

# Добавить к последнему коммиту
git commit --amend --no-edit

# Если уже запушено, нужно force push (осторожно!)
git push origin integration/your_branch --force
```

#### Проблема: Хочу изменить последний коммит

**Решение:**
```bash
# Внести изменения
# Затем:
git add .
git commit --amend -m "новое сообщение коммита"
git push origin integration/your_branch --force
```

## Терминология

### Интеграция

**Интеграция** - это готовый "блок" для работы с внешними сервисами в платформе DBCV. Интеграция позволяет боту взаимодействовать с различными API и сервисами (Telegram, OpenAI, Google Sheets и др.) без написания сложного кода.

**Примеры:** Telegram Send Message, OpenAI Chat Completion, Google Sheets Read

### Пресет

**Пресет** - это готовый "шаблон" для типовых задач в конструкторе ботов. Пресеты упрощают создание сложных логических конструкций.

**Примеры:** IF/ELSE пресет (условное ветвление), Loop пресет (циклы), Delay пресет (задержки)

### Connection Group

**Connection Group** (Группа связей) - это элемент конструктора ботов, который определяет, как бот обрабатывает входящие сообщения или события. Connection Group может быть типа:
- `message` - обработка текстовых сообщений
- `code` - выполнение Python кода
- `integration` - выполнение интеграции с внешним сервисом

### Credentials

**Credentials** (Учетные данные) - это конфиденциальная информация, необходимая для работы с внешними сервисами. Credentials хранятся безопасно и используются интеграциями через CredentialsResolver.

**Примеры:** API ключи, токены доступа, пароли

### Provider и Strategy

**Provider** - это название сервиса, для которого используются credentials (например, "telegram", "openai", "google").

**Strategy** - это способ аутентификации:
- `api_key` - использование API ключа или токена
- `oauth` - использование OAuth авторизации
- `none` - credentials не требуются

### Pull Request / Merge Request

**Pull Request (PR)** или **Merge Request (MR)** - это запрос на добавление вашего кода в основной проект. После создания PR ментор проверяет код и, если все хорошо, вливает его в основную ветку.

### Git ветка

**Ветка (branch)** - это копия проекта, где вы работаете над своей задачей. Каждая задача должна выполняться в отдельной ветке, чтобы не мешать другим разработчикам.

**Формат названия ветки:**
- Для интеграций: `integration/{service}_{action}` (например, `integration/telegram_get_updates`)
- Для пресетов: `preset/{preset_name}` (например, `preset/switch`)

### Registry

**Registry** (Реестр) - это система регистрации всех доступных интеграций в проекте. Каждая интеграция должна быть зарегистрирована в registry, чтобы быть доступной в каталоге.

### Config Schema

**Config Schema** - это JSON Schema, которая описывает параметры конфигурации интеграции. Schema определяет, какие поля нужны для настройки интеграции, их типы, обязательность и значения по умолчанию.

**Поддерживаемые типы полей:**
- `string` - текстовое поле
- `number` - числовое поле (дробные числа)
- `integer` - целочисленное поле
- `boolean` - чекбокс
- `array` - массив (JSON редактор)
- `object` - объект (JSON редактор)
- `enum` - выпадающий список (для string)

### Bot

**Bot** (Бот) - это созданное в платформе DBCV приложение, которое может обрабатывать сообщения, выполнять интеграции и взаимодействовать с пользователями через различные каналы (Telegram, Discord и др.).

### Step

**Step** (Шаг) - это элемент конструктора ботов, который представляет одну операцию или действие. Шаги соединяются между собой через Connection Groups, образуя логику работы бота.

### Channel

**Channel** (Канал) - это способ взаимодействия бота с пользователями. Примеры каналов: Telegram, Discord, VK и др.

### Session

**Session** (Сессия) - это контекст взаимодействия пользователя с ботом. В сессии хранятся переменные пользователя, история сообщений и другая информация о текущем взаимодействии.

### Variables

**Variables** (Переменные) - это данные, которые могут использоваться в боте. Переменные могут быть:
- `bot.*` - переменные бота
- `session.*` - переменные сессии
- `user.*` - переменные пользователя
- `channel.*` - переменные канала

**Пример использования:** `{$user.telegram_chat_id$}` - получить ID чата пользователя в Telegram

### BaseIntegration

**BaseIntegration** - это базовый класс, от которого наследуются все интеграции. Он определяет интерфейс интеграции и методы, которые должны быть реализованы:
- `metadata` - метаданные интеграции
- `execute()` - выполнение интеграции

### CredentialsResolver

**CredentialsResolver** - это сервис, который безопасно получает credentials для интеграций. Интеграции должны использовать CredentialsResolver вместо прямого доступа к credentials.

### Docker и Docker Compose

**Docker** - это платформа для запуска приложений в изолированных контейнерах. **Docker Compose** - это инструмент для управления несколькими контейнерами одновременно.

### API Endpoint

**API Endpoint** - это URL адрес, по которому можно обратиться к API сервера. Например, `/api/integrations/catalog` - endpoint для получения каталога интеграций.

### Swagger / OpenAPI

**Swagger** или **OpenAPI** - это документация API, доступная по адресу `http://localhost:8003/docs`. Здесь можно увидеть все доступные endpoints и протестировать их.
